# 能天使的先古对话

## 文案范围

新增八位赐福先古之民及建筑师的角色专属对话，每位三组，中英各 27 组、92 句台词。完整台词以运行时文件为准：

- [简体中文](../AK_Exusiai/localization/zhs/ancients.json)
- [英文](../AK_Exusiai/localization/eng/ancients.json)

沿用现有角色介绍的时间背景：企鹅物流资深员工、苹果派物流老板。能天使和新约能天使的六套外观仍是同一角色，使用同一套对话，不读取本机外观配置决定剧情。

## 接入合同

仅增加两份 `ancients.json`，无需修改角色 ID、注册、入口或新增 Harmony 补丁。游戏将本 Mod 的同名本地化表合并到 `ancients`；RitsuLib 在原版 `PopulateLocKeys` 前自动追加已注册角色的台词。

键格式：`<先古 ID>.talk.AK_EXUSIAI_CHARACTER_EXUSIAI.<组号>-<行号>[r].<ancient|char|next>`。

- 组号、行号均从 0 连续编号；中英键必须完全一致。
- 每组除最后一句以外都提供 `.next`；最后一句交还原版奖励选项或结局按钮。
- 一组若可重复，所有行和按钮均带 `r`，不可只给第一行加。
- 普通先古三组使用框架默认的历史访问次数 0、1、4，即该角色第 1、2、5 次访问；第 2 组进入重复池。
- 全存档首次拜访某位先古时，原版 `firstVisitEver` 优先；这是原版流程，不保证新建存档第一面就显示专属台词。已有较多访问次数的存档会进入重复池，不强行重置进度。
- 建筑师按角色历史胜场数 0、1、2 选择，后两组可重复。三组显式设置 `-endattack: Both`，保留原版双方攻击、计分和胜利结算；不把结尾变成空对话。
- 不增加自定义随机源，不写存档，不按本机皮肤分支。实际联网体验仍需双端同包回归。

## 验证与验收

结构检查使用 PowerShell 7：

```powershell
.\tools\validate_ancient_dialogue.ps1
.\tools\validate_ancient_dialogue.ps1 -PckPath '<实际部署的 AK_Exusiai.pck 路径>'
```

检查九个事件、连续编号、唯一说话人、按钮、成对标签、中英键一致、建筑师结束标记；可选 PCK 检查会逐字节比较打包文本和源码。

2026-09-20 额外通过临时隔离测试程序，分别调用实际 RitsuLib 0.5.20/0.6.2 的 `GetDialoguesForKey` 和本机游戏的 `PopulateLocKeys`、`GetValidDialogues`：中英各 27 组均可解析，访问次数 0/1/2/3/4/5/20/100 均有可选对话，原版首次访问优先、非本角色隔离、重复池与建筑师攻击标记通过。测试程序仅在独立进程装入内存本地化表，没有读取或改写玩家进度；它不等于运行完整游戏。

仍待实机验收：

1. 备用测试档中逐一访问八位先古，核对中英文气泡排版、按钮和奖励选项；不要为测试覆盖正式进度。
2. 检查原版首次拜访、角色第 2/5 次拜访、已有高访问次数存档和切换语言。
3. 完成建筑师对话，确认攻击演出、计分、胜利和返回流程没有卡住。
4. 两台安装相同 DLL/PCK 的客户端，检查多人访问、退出重入及不同本机外观下的对话。
5. 启动日志确认 `ancients.json` 合并成功、Mod 自动注册与 `ModelDbDefer` 完成，并检查没有缺失对话键警告。
