# 卡牌特效与音效管理器：首版方案

状态：首版已实现，位于 `tools/card_effect_manager/`；实际验证与剩余限制见 `PROGRESS.md` 和工具 `README.md`。下文保留最初方案及调查依据。
日期：2026-09-06。

## 已确认范围

- 独立 Godot 管理窗口，沿用 `tools/card_art_manager` 的操作布局；原版效果在游戏内真实试播。
- 以攻击牌为主，同时支持技能、能力牌打出时的简单特效和音效。
- 效果库以尽可能完整覆盖本机当前游戏中的常规及特殊攻击演出、音效为目标，明确包含“华丽收场”“超能光束”等专用演出；少量代表效果仅用于起步验证，不是最终交付范围。
- 管理对象是出牌时的发射、飞行、命中特效和声音。人物动画继续使用已导入的外观及其 Attack/Cast 映射。
- 核心操作是“选择能天使卡牌 → 选择原版效果预设 → 游戏内试播 → 微调 → 导出配置”。

## 本机代码调查

依据：当前安装的 `sts2.dll`，SHA-256 为 `0861BFA1DF347538D932F22D580E75420F08082792EB914E53B4882764ACDBE9`。通过工作区 ILSpy 按类型检查；未进行游戏内效果验证。项目当前实际 NuGet 引用为 RitsuLib 0.5.18，以 `AK_Exusiai.csproj` 为准。

### 特效并非统一的“动画文件”

`MegaCrit.Sts2.Core.Models.Cards.Hyperbeam.OnPlay` 的攻击部分：

1. 建立原版 `AttackCommand`，以所有敌人为伤害目标。
2. `WithAttackerAnim("Cast", 0.5f)` 调用角色施法动作，并等待。
3. `BeforeDamage` 创建 `NHyperbeamVfx`，添加到战斗特效容器，然后等待约 0.5 秒。
4. 为敌人创建 `NHyperbeamImpactVfx`，之后由攻击命令结算伤害。
5. 原卡还会施加自身减集中能力；复用视觉预设时不能执行这部分原卡玩法。

`NHyperbeamVfx` 自身又负责蓄力粒子、激光显示、收尾、两次震屏和声音：

- 音效事件：`event:/sfx/characters/defect/defect_hyperbeam`。
- 内部蓄力时间 0.525 秒，激光显示时间 0.5 秒；不能把所有等待简化为一个可随意拖动的时长。
- `Create(Creature, Creature)` 使用角色 `VfxSpawnPosition`；故障机器人另外加 `Defect.EyelineOffset`。能天使不会自动获得故障机器人的眼部偏移。
- 提供 `Create(Vector2, Vector2)` 重载，可作为适配能天使发射位置的入口，但枪口坐标和各外观效果仍需实测。

`SweepingBeam` 也通过专用 VFX 类及卡牌代码组合完成，说明复杂效果需要逐个建立小型适配器，不能仅扫描 `.tscn` 后全部当通用素材播放。

### 华丽收场：纳入首批特殊预设

进一步检查了当前 DLL 的 `GrandFinale.OnPlay`、`NGrandFinaleVfx` 和 `NGrandFinaleImpactVfx`：

- 出牌先创建主演出 `NGrandFinaleVfx`，并等待它定义的 `totalAnticipationDuration`；主演出包含聚光灯、粒子、斩击及震屏。
- 随后的攻击通过 `WithHitVfxNode(NGrandFinaleImpactVfx.Create)` 为实际受击目标创建命中特效，通过临时音频路径播放 `blunt_attack.mp3`。这里只确认了代码中的显式音频调用；场景内音频轨道和其他依赖仍须继续检查。
- 主演出具有位置参数重载；命中特效分别接收目标中心与脚底坐标。预设需保留两种锚点，不能都放在目标中心。
- 原卡的“抽牌堆为空才能打出”、伤害和升级数值属于原卡机制；绑定这套演出不会把这些规则带入能天使卡牌。
- 此项后续已完成适配，并在能天使单人战斗试播；完整演出仍沿用原版节点，枪口与各外观可继续校准。

### 通用攻击接口

检查类型：`MegaCrit.Sts2.Core.Commands.Builders.AttackCommand`、`VfxCmd`、`SfxCmd`、`NAudioManager`。

- `FromCard` 自动使用角色默认攻击动作。能天使当前 Attack/Cast 延迟均为 0.35 秒，外观映射已存在。
- `WithAttackerFx` 设置攻击方特效/音效；`WithHitFx` 设置命中特效/音效。
- `WithHitVfxNode` 支持以实际命中目标创建专用节点；`SpawningHitVfxOnEachCreature` 区分群体中心和逐个敌人受击。
- `OnlyPlayAnimOnce` 只约束攻击方动作/特效/声音及其后置回调；命中侧和 `BeforeDamage` 仍逐段执行，不能把它当成“所有声音只播放一次”。
- `BeforeDamage` 和 `AfterAttackerAnim` 的设置会替换原回调。接入时必须保留并正确组合已有逻辑，不可覆盖卡牌原有行为。
- 当前实现中命中音效先于 `WithWaitBeforeHit` 的等待播放。要微调音画同步，需要明确调节的是哪个阶段，不能只相信方法注释。
- 原版音效同时存在 FMOD `event:/...` 和临时文件两条路径。项目 `ChargingMode` 的 `dagger_throw.mp3` 使用临时文件参数；两者不能混用。
- 特效依赖游戏的资源缓存、节点脚本、战斗容器和音频环境。独立管理器完整复现它们尚未验证，首版采用游戏内试播。

项目参照：`AK_ExusiaiCode/Cards/LaserCannon.cs` 当前是钝击命中特效；`ChargingMode.cs` 是三段斩击加临时音效；`Characters/Exusiai.cs` 管理角色动作。当前 `Debug/ExusiaiConsoleCmd.cs` 是联网玩法测试入口，视觉试播应采用独立的本地开发入口。

| 原版效果库 | 尽可能完整收录常规和特殊攻击效果，以“华丽收场”“超能光束”等原版卡名为入口；提供“组合预设 / 单独特效 / 单独音效”标签。展示用途、来源、适用目标、附带音效/震屏、适配状态；收藏常用项。 |

| 位置与时序 | 默认使用预设时序；高级折叠区支持已适配参数，例如发射点偏移、目标中心/脚底、出手到命中的等待。缩放等只对验证可调的效果开放。 |

| 快速复用 | 复制/粘贴配置、保存个人预设、批量应用到所选卡牌。批量应用先列出将覆盖的卡牌，支持撤销。 |

### 效果库完整性与选择体验

**收录范围**

1. 全部原版角色、无色及衍生卡中的攻击演出：包括普通斩击、钝击、闪电等通用受击效果，以及投射物、光束、连续攻击、全屏/群体等专用组合。
2. 上述演出涉及的出手、飞行、命中和收尾音效，包含 FMOD 事件与临时音频文件。能独立复用的声音提供独立条目；只能随演出播放的声音仍可搜索，并标记“随预设播放”。
3. 扫描怪物、召唤物及其他战斗攻击来源的特效和声音，作为额外分类提供；优先适配可脱离原来源复用的部分。这是资源库的扩展，不意味着编辑器同时接管这些来源的玩法。
4. 继续收录适合技能/能力牌的简单自身或目标特效。背景音乐、UI 提示音、完整人物骨骼动作不混入默认攻击效果列表。

**发现与适配流程**

- 以本机当前游戏为基线，先枚举原版卡牌和攻击来源，再追踪攻击命令、直接 VFX/SFX 调用、共用助手、专用节点和场景依赖。补查场景动画轨道触发的音频及动态构造资源名，不能只用字符串搜索结果代替完整清单。
- 用可读取的场景资源目录、音频事件目录和临时音频目录交叉核对。枚举方式在实现时按本机实际可用接口验证；无法识别的条目记录原因，不猜测路径或把扫描成功等同于可播放。
- 抽取“原版来源 → 组合演出 → 独立特效/声音”的关联；同一资源去重，但保留所有来源卡名作为搜索别名。即使两张牌共用资源，时序或重复规则不同，也保留各自的演出预设。
- 常规效果按共同调用方式批量适配；复杂效果逐类接入。每个特殊预设至少实际试播一次，确认内置声音、锚点、清理和正常出牌时序。相同基础适配器可共用，但不能据此推定所有特殊场景已经验证。
- 每个原版攻击来源都必须有审计结果：已映射、确认无独立演出、尚待调查或存在具体依赖限制。对难以复用的效果保留条目、原因及后续工作，不能静默省略。

**UI 与状态**

- 支持中文卡名、英文卡名、资源名及事件名搜索；来源角色/怪物、效果类别、单体/群体、是否带声音、收藏和适配状态筛选。
- 默认展示已适配且可选择的条目，同时提供“显示全部已发现条目”；未适配项可查看详情和限制，不允许导出为已经可用的配置。已适配但尚未验证与已验证使用不同状态。
- 同一处同时提供“使用整套演出”和可用的“只选命中/只选声音”，让用户无需理解内部资源路径也能操作。
- 效果库展示可查看的覆盖统计和缺项清单，分别统计原版攻击来源覆盖与去重资源覆盖，避免用大量重复音效条目制造“全部收录”的假象。
- 建议生成 `catalog_audit.json` 审计元数据，记录游戏程序集指纹、来源、依赖、适配器、状态和具体限制。游戏更新后保留绑定，对新增/缺失资源提示复查；受影响的旧验证状态转为待复验。

### 内置音效处理

超能光束的音效和震屏由其 VFX 内部触发。首版先完整保留，并在配置中显示“预设自带”；不再额外叠播同一个声音。不承诺所有预设都能单独静音、调音量或替换内置声音。仅当适配器实现并验证该能力后，才启用相应控件；额外叠加声音由用户明确选择。

### 非攻击牌

支持出牌开始或卡牌效果完成时，在自身/已有目标处播放简单 VFX/SFX。默认沿用当前人物动作。保留需要选牌、取消、自动打出时的实际执行时点；持续能力以后每回合/每次触发的效果、召唤物攻击不纳入首版通用编辑器。

## UI 布局

保持卡图管理器的左素材、中预览、右卡牌配置结构和深色视觉风格；沿用界面缩放、可拖动分隔栏、记忆栏宽、搜索和底部状态栏。

- 顶栏：工具名称、界面缩放、重新扫描、导出配置、游戏连接状态。
- 左栏：组合预设/特效/音效，搜索与分类，效果列表，来源和附带行为说明。
- 中栏：角色与目标的简化位置图，标明是位置示意；下方用“出手 → 发射 → 命中 → 收尾”阶段条说明预设，不做自由多轨时间轴。提供试播所选素材、试播当前卡牌效果、停止试播。
- 右栏：可搜索卡牌选择、缩略图和规则摘要、基础/升级切换、效果预设、音效、重复策略；高级区折叠位置和时序设置。
- 底栏：自动保存状态、试播反馈、待验证提示；导出时显示进度。

配置流程示例：“激光炮” → 左侧选“超能光束” → 应用预设 → 保留预设声音 → 游戏中试播 → 调整发射点 → 真实出牌确认 → 标记验证并导出。只应用演出，不引入原卡减集中等规则。

## 配置与运行时接入建议

拟建 `tools/card_effect_manager/`，名称暂定“能天使卡牌特效与音效管理器”。

- 可提交编辑清单：`tools/card_effect_manager/card_effect_manifest.json`。
- 预设目录：稳定的预设标识、中文名、来源卡牌、适配器标识、可调参数、内置音效、目标限制和验证信息。自动扫描只产生候选条目，确认适配后才标记可绑定。
- 正式输出：`AK_Exusiai/config/card_effects.json`，随 Mod PCK 发布。
- 运行时代码：统一读取配置，调用少量 C# 效果适配器。卡牌在明确的攻击构造或效果阶段接入一次，后续日常修改不必逐张改 C#。
- 未配置卡牌沿用现有表现。使用现有稳定卡牌 ID 绑定；基础配置和升级覆盖分开保存，工具按中文名展示。
- 清单保存 schema 版本；导出校验卡牌/预设是否存在、参数范围和目标兼容性。游戏资源以路径或事件标识引用，不复制整套游戏素材进仓库。
- 简单攻击优先用已有 builder 接口；复杂效果如 Hyperbeam 由专用适配器创建节点。保留原有 CardPlay、伤害、目标选择和弹药流程；随机攻击从实际命中目标取位置，不能另外抽随机目标。
- 本地 UI 设置和游戏路径继续读取本机配置，不写入共享清单。

### 开发试播桥接

建议首次安装试播支持后，在单人战斗中显式启用本地开发模式。管理器经本地文件收件箱发出限定的“预设/声音标识、卡牌标识、参数、目标”请求，游戏在主线程调用同一套演出适配器，并回写请求编号与结果。不执行来自文件的任意脚本。

试播只播放视觉/音效，不打出整张牌、不调用伤害命令、不消耗弹药；目标、段数可在试播中模拟。真实出牌回归单独进行，验证实际段数和游戏时序。结束战斗、切场景和停止试播时清理本工具创建的节点及循环声音。

编辑配置通过开发覆盖文件在空闲时热重载，固定本次出牌使用的配置快照；发布模式读取 PCK 内正式配置。开发覆盖默认关闭、仅本地单人启用。已有联网测试命令不直接承载本地试播，以免把本机配置和模拟行为带入多人流程。

桥接的实际目录、Godot 文件访问及节点清理能力在第一阶段原型中验证。正式发布仍走项目正常构建和部署流程。

## 实施顺序与验收

1. **建立完整候选目录并验证核心闭环**：扫描全部原版攻击来源；用普通斩击、超能光束、华丽收场、自身简单特效和两类音效，验证“配置 → 游戏内试播 → 实际卡牌调用”；优先检查激光起点、聚光灯/脚底锚点、内置声音、切场景清理。
2. **实现管理窗口**：卡牌目录、效果库的搜索/筛选/关联/状态、三栏 UI、保存/撤销/导出、连接和试播反馈。先接入激光炮、三段攻击和一张技能/能力牌作为代表。
3. **完成广泛效果适配与卡牌覆盖**：按候选目录批量覆盖常规攻击特效和声音，逐类适配特殊演出，检查怪物等额外来源的可复用效果。接入其余卡牌，补齐 AOE、随机目标、升级覆盖、批量应用和外观校准。

首版完成标准：使用者无需改 C# 即可给已接入卡牌更换已支持的演出；修改后可快速游戏内试播，正式导出后重启游戏仍生效。普通攻击、多段、AOE、随机目标、无可用目标、击杀中断、重放、六套外观、普通/快速模式以及技能选牌阶段均有代表性验证。机制回归确认伤害、弹药消耗、目标和 Hook 次数不变。

效果库验收另需：全部枚举到的原版攻击来源均有明确审计结果；通用特效/音效和已确认可复用的特殊演出完成适配；“华丽收场”“超能光束”作为明确验收项。交付列出扫描数、已支持数、已验证数和无法支持的具体原因。不得只交付几项示范预设而宣称完成，也不得在没有完成来源与依赖核对时宣称“包含游戏全部效果”。

不纳入首版：新建人物动画、任意脚本编辑、自由多轨剪辑、所有游戏场景一键通用化、独立窗口完整重建游戏音视频运行环境。内置声音的拆分替换和复杂枪口骨骼跟随按具体预设后续增加。
