# 统计实施说明

更新：2026-10-08。[主站](https://exusiai.zzt.si/) · [GitHub Pages](https://jimmyzzt.github.io/AK_Exusiai/)。只公开聚合统计，D1 / Workers 使用免费档位。

## Mod 采集

`stat/mod/` 使用 RitsuLib 生命周期事件，授权后仅上传新结束的本机能天使玩家局。不会扫描旧存档，不捕获框架的原始跑局信封。授权申请、请求与队列事件名保持原值，HTTP 正文升级为 `exusiai.run.v2`，服务器同时接受 v1。

v2 除原有计数外，记录启用 Mod 的公开名称 / 工坊 ID、每幕实际层数与完成标记、每次本 Mod 卡牌奖励的幕 / 层 / 升级版本 / 选择结果、各幕获得 / 升级 / 删除、战斗遭遇 / 本机损血 / 回合数。`ActEnteringEvent` 在下一幕开始前保存本 Mod 卡组和永久遗物摘要；局终补充当前幕摘要。中转遗物排除在永久栏之外。跨幕缓存为 `user://exusiai-stat-acts.json`，只保存 HMAC 局键和本 Mod 内容 ID；写入使用临时文件替换。载入旧局没有缓存时，过去幕末持有状态保持未知。

不上传 Steam / 网络玩家 ID、姓名、种子、队友卡组、日志、本地路径或框架会话标识。局 ID 使用本机凭证 HMAC，服务仅保存凭证单向摘要。Mod 工坊 ID 是公开内容标识，与玩家身份不同。Cloudflare 接收请求时仍处理 IP 等网络元数据。

本机凭证位于 `user://exusiai-stat-identity.txt`。RitsuLib 管理授权和有界队列；适配器逐局发送，D1 原子批次成功后确认，断网 / 429 / 503 重试。重复局 ID 及并发重试不重复计数，随机写入 nonce 保护所有明细、模型和 Mod 使用数。没有删除数据、刷新身份或查询凭证功能。

授权文案由 `AK_Exusiai/localization/statistics/zhs.json`、`eng.json` 统一管理，设置仍只有授权开关和网站入口。编译 / 工坊运行时基线为 RitsuLib 0.6.7，与本机游戏 0.111.0 API 核对。主工程、测试工程和 `Directory.Build.targets` 均禁用 RitsuLib 自动复制。

## 统计口径

默认单人、标准、前三幕、全部 Mod 组合，排除未完成第三幕的放弃局。完成第三幕即通关；更晚的失败或放弃不影响默认结果。所有幕使用完整对局结果；单幕只筛选该幕的内容事件，结果仍以第三幕为终点。

范围终点持有按该幕快照计算；同局同牌同时有基础和升级版，合并模式只计一次。区分升级版时基础为0，任意升级等级归为1；v1 没有升级维度，不混入区分模式。旧对局存在额外幕选择时，可确认已通过第三幕；安装额外幕 Mod 却缺少完成证据时，第三幕结果保持未知。终点持有 / 层数缺失也不猜测，相关分母不包含这些未知样本。旧局的分幕覆盖仅限保存过奖励选牌的幕。

目录仅包含本 Mod 的105张卡牌、9件角色遗物、20件先古遗物。指标定义、最低样本要求及参考站差异见 [指标方法](METRICS.md)，网页悬停名称可查看简明描述。

版本与内容修订独立：Mod 清单仍1.1.0，本次统计修订为 `cards-v1.3-stat-v2`。不改已发布内容 ID，不追溯重写旧记录。

## Mod 标签

`mod_catalog` 按真实新入库玩家局累计使用次数，初始迁移从旧分组计数合并。对外按使用数降序展示。能天使和清单必需依赖 RitsuLib 不参与手动、标签黑名单或白名单过滤。

只保留 Steam 官方19种分类标签，自定义和语言标签丢弃。主要标签优先级：Characters → Acts → 玩法扩展（Cards / Relics / Expansion 等）→ Tools & APIs → QoL / Utility → Cosmetics → Audio → Misc / Humor；没有匹配为无标签。白名单允许没有勾选标签，此时只保留没有额外 Mod 的对局；手动排除与标签规则同时生效。

每15分钟定时触发，处理最多16个已有工坊 ID、6个缺少 ID 的 Mod；未知项优先，按使用数排序。每个没有 ID 的项最多一次公开搜索，每次搜索最多8个候选，合并为一次公开详情请求。搜索只接受唯一规范化名称精确匹配、且属于 STS2 的候选，避免把相似 Mod 的标签误分配。无法找到时标无标签。条目检查后24小时重新排队；若积压超过每日批次容量，全库轮询可能超过一天。Steam 403 / 429 全局冷却6小时，其他失败30分钟，保留已有标签。页面刷新不访问 Steam。

使用 [Steam GetPublishedFileDetails](https://partner.steamgames.com/doc/webapi/ISteamRemoteStorage#GetPublishedFileDetails) 和公开工坊搜索，无 Steam 私人密钥、登录 Cookie 或作者身份采集。

## API、缓存与迁移

- `POST /api/upload`：Bearer 凭证，v1 / v2 严格白名单，正文最多256KiB，IP每分钟30次、每安装每日30局。
- `GET /api/stats`：公开聚合。过长筛选可 `POST /api/stats`，正文仅 `{ "query": "URL查询字符串" }`，GET / POST 共用缓存键。
- `GET /api/health`：上传开关和服务信息，不是数据库就绪探针。没有逐局或玩家查询接口。

筛选：party、mode、abandoned、from/to（UTC）、version、revision、ascension（A0–A10）、act（standard/all/1/2/3）、split=1、可重复exclude和tags、tag_mode=black/white。最多512个手动排除。只公开聚合 CSV。

新迁移 `0002_analysis.sql` 追加明细、模型和 Mod 库，不修改0001，不删除旧局。聚合查询读取规范表，不读取原始 payload。个人模型和历史基线在新局入库前计算并冻结；旧局没有明细时不补造战斗或升级状态。

每个筛选组合复用15分钟快照；边缘命中不读 D1，冷边缘只读一条快照，过期 / 首次组合才聚合。最多保留128个查询快照，淘汰不会删除对局。刷新不强制重算。每15分钟定时刷新默认统计及一批 Mod 标签；其他筛选按需更新。故障回退已有快照 / 浏览器缓存，无缓存显示不可用。

原始记录当前无到期策略，无自动清理或付费升级。公开客户端无法提供可靠反作弊证明，异常记录需维护者复核。免费配额耗尽时上传与新查询可能暂停；队列容量有限，满库再讨论处理。

## 构建与双站同步

在 stat 目录运行 `npm ci`、`npm run build`、`npm run check`、`npm test`。本地先 `npm run migrate:local` 再 `npm run dev`；本地使用隔离 D1 和静态资源，不代理线上页面。网页、Node 和测试目录由 `.gdignore` / PCK 导出规则隔离；只显式编译 mod 的 C#。

构建按 `tools/card_art_manager/card_art_preview.gd` 技能牌可视范围真正裁切所有卡图，再生成 WebP；原图不改。每张图携带内容哈希，修改后更新 URL。Hero 使用新约能天使精一立绘。源码中的名字 / 分类和中英本地化自动生成内容目录。

main 推送卡图、立绘、本地化、相关代码或 stat 变更，会触发 `.github/workflows/stat-pages.yml`：构建、类型检查、测试、官方 Pages artifact 部署。Pages 发布模式为 GitHub Actions。Worker 静态路径共享同一公开 Pages 发布，保留最近本机部署 ASSETS 为故障回退；API 始终由 Worker / D1 提供。代理不转发浏览器凭证 / Cookie / 筛选，静态更新缓存约60秒，无需 Cloudflare CI 密钥。静态刷新不访问 D1。

Worker / 数据库代码不会随卡图推送自动部署，需要登录的维护者执行发布。`npm run publish` 做本机构建检查、远程迁移和 Worker 部署，保留 gh-pages 静态归档并触发 main 的 Pages 工作流；需先把对应源码提交推送到main，两站才能一致。不会替维护者发布工坊。
