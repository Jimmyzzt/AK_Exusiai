# 指标方法

单位为能天使玩家局。胜利终点默认第三幕，所有幕模式使用完整结果。未知结果不进入胜率分母，持有率分母仅为已知范围终点卡组的局数。

| 名称 | 计算 | 覆盖 |
| --- | --- | --- |
| 选取率 | picked / offered | v1与v2，按奖励次数 |
| 持有胜率 | 持有且通关局 / 结果已知的持有局 | 每玩家局去重 |
| 持有率 | 持有局 / 范围终点持有状态已知局 | 幕末 / 局终快照 |
| 选后胜率 | 选择过且通关局 / 结果已知的选择局 | 跨幕合并仍每局一次 |
| WAR | Σ(actual win − expected win)，全部提供 | 仅v2 |
| pWAR | Σ(actual win − expected win)，仅实际选取 | 仅v2 |
| pWAR% | 100 × pWAR / 选取次数 | ≥10次v2选取 |
| 逐幕 WAR / pWAR / pick% | 同上，只取对应幕的奖励 | 默认前三幕 |
| 后期偏好 ΔPick | 100 × OLS(picked, cumulative floor) 的斜率 | ≥20次v2提供，单位pp/层 |
| 后期贡献 ΔWAR | 100 × OLS(win − expected, cumulative floor) 的斜率 | ≥20次v2提供，单位pp/层 |
| 损血变化 ΔHP | 选取后战斗损血 − 该遭遇历史平均损血，再对战斗求均值 | ≥10个v2选取玩家局；基线≥5场 |
| 回合变化 ΔTurns | 同上，回合数代替损血 | 同上，负数更快 |

WAR / pWAR 参考 [Spirebird 指标说明](https://spirebird.com/stat-descs.js) 与 [计算引擎](https://spirebird.com/engine.js?v=pick-rate-20261005)，不是普通胜率差，也不是卡牌因果收益。

## 预期胜率

当前估计器为 `personal-logistic-floor-v2`，按安装凭证摘要、进阶、人数、模式、胜利终点分别建立个人模型。上传前读取此前样本，当前局不得进入自身基线。首次个人概率 `(此前胜局+1)/(此前局数+2)`，logit均值、初始方差4；每局方差漂移0.02，按逻辑 Kalman 更新个人模型。

```text
expected = sigmoid(logit(personal) + logit(floor_rate) - logit(overall_rate))
```

rate 在取 logit 时限制到0.01–0.99。楼层基线按进阶 / 人数 / 模式 / 终点 / 幕 / 幕内层数聚合，至少5个样本才使用，否则采用总体率；无总体样本时采用0.5。基础和升级版共用玩家基线，分别累加卡牌提供 / 选取残差。数据在上传顺序中累积，离线上传延迟不会回溯改写已冻结预测。

与 Spirebird 的差异：本站没有完整原版社区长期历史，不执行其≥50局逻辑回归重校准、按数据优化漂移或初始20局总体先验；采用上述明确的平滑与固定漂移。ΔPick 是原始选择趋势，没有复现参考站的选牌 Elo 残差。战斗差值基线按上传前相同进阶 / 人数 / 模式 / 幕 / 遭遇的已有v2战斗建立，固定在当前战斗记录中；参考站使用的数据和期望建模不同。各指标都受玩家偏好、存活时长和 Mod 环境影响。

## 覆盖与展示

旧数据继续贡献选取、持有及获得等可确认指标，WAR、战斗差值、升级区分显示“—”。旧局没有第三幕证据时，不用完整局终卡组冒充第三幕末卡组。缺失分幕记录或幕末缓存保持未知。

零分母 / 低于指标最低样本显示“—”，低于30个对应样本标小样本。逐幕选择玩家局、跨幕选择玩家局与同时持有基础 / 升级版的合并玩家局分别去重。遗物中转副本不计入永久持有；同ID / 同层的不同获得来源取最大计数，可能低估同层重复获取或获取后已失去的特殊情况。
